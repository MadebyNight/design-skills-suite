## 1. 应用场景

- **主题化首页设计**：输入首页主题、目标用户、内容要求和视觉限制，在固定六模块边界内生成支付宝小程序首页配置、素材、静态原型和运营配置建议。
- **活动落地页设计**：输入活动主题，在七类白名单模块内规划模块集合与顺序，生成独立落地页设计包；未提供具体文案时，可根据主题生成受字段长度约束的设计文案。
- **首页—落地页联动**：在同一批次中生成首页与多个落地页，用任务内 `landingKey` 建立离线预览关联，便于评审完整活动链路。
- **文本生成视觉素材**：把页面主题、槽位用途、目标比例、安全区和禁止内容转换为结构化素材请求，再调用图片 provider 生成初始图片。
- **参考图路由（有条件）**：可把用户上传的图片绑定到指定页面槽位；仅当外部注入的图片 provider 显式声明 `asset.reference-images` 能力时才会传入参考图。当前内置 fal.ai 与 OpenAI-compatible binding 不消费参考图，会记录 warning 并降级为文本生成。
- **图片自动适配**：生图结果不满足目标比例或格式时，由 OpenPhoto 按 `cover` 或 `contain` 规则执行裁切、缩放和导出，再回填页面槽位。
- **多素材并发处理**：同一页面最多并发执行五个独立生图请求，减少多槽位任务的等待时间；图片适配和 checkpoint 写入保持串行以维持一致性。
- **批量页面生产**：通过一个结构化请求依次生产多个首页或落地页，并输出统一离线入口、配置、素材、原型、截图和运行记录。
- **中断恢复与失败重试**：使用文件 checkpoint 恢复 pending 或 interrupted 项，仅重试 failed 项；已经成功且校验仍有效的素材不会重复生成。
- **素材策略与复用**：可按页面槽位选择 `generate` 或 `reuse`，并区分 required 与 optional，减少重复生图和无效成本。
- **受控任务执行**：自动校验 Schema、组件边界、素材比例、文件引用和设计包完整性；越界请求返回结构化拒绝，不修改组件快照。
- **多 Agent 宿主复用**：同一组 manifest、`SKILL.md` 和 CLI 可挂载到 Codex、Claude Code、OpenCode 等宿主，降低重复集成成本。

## 2. 人工提效

### 2.1 结论

在“需求已经明确、使用既有组件、业务资源由外部系统提供”的标准页面设计任务中，预计可将单页人工投入从约 **4–8 人时降低至约 2 人时**：

- 单页预计减少 **2–6 人时**；
- 人工投入预计降低 **50%–75%**；
- 五页批次预计减少 **10–30 人时**。

标准场景的中位估算为：单页从约 6 人时降低至约 2 人时，减少约 **4 人时，降幅约 67%**。

这些数字是基于标准工作分解的**流程模型估算**，不是当前仓库已经完成的真人对照实验，也不是对所有页面的交付时长承诺。当前尚未完成真实图片 provider 的重复耗时评测和人工视觉可用率盲评。

### 2.2 估算模型

| 工作环节 | 传统人工流程 | 使用本套件后的人工职责 | 预计变化 |
|---|---:|---:|---|
| 理解需求与整理约束 | 0.5–1 人时 | 0.25–0.5 人时 | 结构化 Brief 减少反复整理 |
| 页面规划与模块组合 | 0.75–1.5 人时 | 0–0.25 人时 | Skill 在白名单内自动规划 |
| 素材提示词、生成与尺寸处理 | 1.5–3 人时 | 0.25–0.5 人时 | 自动生成、比例验收和适配 |
| 原型组装与配置整理 | 0.75–1.5 人时 | 0–0.25 人时 | 配置、原型和指南同源生成 |
| 检查、评审与交接 | 0.5–1 人时 | 0.75–1 人时 | 自动检查后仍保留人工视觉评审 |
| **合计** | **4–8 人时** | **约 1.25–2.5 人时，规划按约 2 人时** | **标准场景减少约 2–6 人时** |

模型按照相同复杂度配对估算：低复杂度任务约 `4 → 2` 人时，标准任务约 `6 → 2` 人时，高复杂度但仍在受控边界内的任务约 `8 → 2` 人时。因此不使用“最小传统工时减最大套件工时”来计算降幅。

### 2.3 计入与不计入范围

计入自动化收益的环节：

- 页面结构规划和受控文案生成；
- 页面视觉素材请求、生成、比例适配和回填；
- 静态原型、配置文件、配置指南和设计包生成；
- Schema、组件约束、素材和本地文件引用校验；
- 批量执行、合法素材复用、中断恢复和失败项重试。

不计入收益的环节：

- 真实商品、优惠券、价格、库存和营销资源确认；
- 生产素材上传及资源 ID 映射；
- `jumpUrl`、`pageCode`、生产路由和活动时间确认；
- 草稿保存、发布、缓存刷新、真机验收和上线审批；
- 品牌负责人或设计师的最终视觉判断及返修时间。

系统执行时间也不等于人工工时。真实图片生成的排队、模型响应和重试会影响自然时长，但 Agent 运行期间通常不需要人工持续操作。

### 2.4 建议的实测方法

后续验证提效数字时，应选择相同 Brief 和组件边界，分别记录人工流程与 Skill 流程：

1. 人工主动操作分钟数；
2. 系统等待分钟数；
3. 首次交付通过率；
4. 人工修改次数及修改分钟数；
5. 最终可用设计包比例；
6. 单页图片 API 成本。

至少覆盖首页、单落地页和“首页 + 两个落地页”三类任务，每类重复执行后再更新本文估算。

## 3. 产品背景

支付宝活动页面设计通常包含需求整理、组件选择、视觉素材生成、尺寸处理、页面组装、检查和交付。各环节由不同工具完成时，容易出现以下问题：

- 需求和页面配置缺少统一结构，交接依赖口头说明；
- 生图结果与页面槽位尺寸不一致，需要人工反复裁切；
- 首页、落地页和素材之间缺少可追溯关联；
- 批量任务中断后难以判断哪些页面或素材需要重做；
- Agent 容易生成超出组件库和生产系统边界的自由页面；
- 静态原型、配置建议和素材清单可能各自维护不同事实。

本产品把上述步骤拆为可独立调用的 Skill，并通过公共合同和可选编排层组合为一条受控设计链路。

## 4. 产品定位

### 4.1 一句话定位

把支付宝页面设计需求转换为可评审、可追溯、受组件边界约束的视觉设计包。

### 4.2 产品形态

- 一组可独立安装或组合调用的 Agent Skill；
- 一组稳定的 JSON Schema、manifest 和 capability ID；
- 首页、落地页和图片生成的独立 CLI；
- 面向多页任务的批量编排 CLI；
- 基于既有支付宝组件快照的静态原型生成工具链。

### 4.3 非产品定位

本产品不是：

- 生图工作台或通用图片编辑器；
- 自由网页生成器或页面搭建后台；
- 完整支付宝小程序前端；
- 商品、优惠券或营销资源管理系统；
- 生产页面保存、发布或回滚系统。

## 5. 产品目标

### 5.1 当前目标

1. 让 Agent 能在已确认的组件和模块边界内生成首页或落地页视觉方案。
2. 让页面规划、生图、图片适配、回填、原型和交付检查形成可执行链路。
3. 让每项交付可通过配置、文件哈希、组件来源和 Skill 版本追溯。
4. 让批量任务能够恢复中断、重试失败并复用已验证素材。
5. 让同一 Skill 套件可被多个 Agent 宿主读取和调用。

### 5.2 成功标准

- 合法输入可生成通过公共 Schema 校验的设计包；
- 页面只使用允许的组件和模块，不引入自由 DOM、class、style 或 script；
- 必填视觉素材经过请求合同规定的比例验收后回填；
- 原型引用的本地素材和样式文件实际存在；
- 批次可区分 succeeded、partially_failed 和 failed，并保留恢复所需状态；
- 不把设计交付物描述为生产保存、发布或真机结果。

## 6. 目标用户

| 用户 | 主要需求 | 使用方式 |
|---|---|---|
| 产品负责人 | 快速评估活动页面方向和交付完整性 | 查看统一入口、原型、配置与边界说明 |
| 运营人员 | 根据主题取得可配置的页面方案 | 提供 Brief，检查配置指南并补业务资源 |
| 视觉设计师 | 减少重复素材制作和尺寸处理 | 评审生成素材与原型，聚焦视觉判断和必要返修 |
| Agent 使用者 | 在不同宿主中执行相同设计任务 | 加载 manifest / `SKILL.md` 并调用 CLI |
| 工程接入方 | 将设计产物适配到外部业务系统 | 消费版本化配置合同和相对路径素材 |

## 7. 产品工作流

```text
DesignBrief
  → 页面 Skill 规划受控配置
  → 生成待补 AssetRequest
  → 图片 provider 生成初始素材
  → OpenPhoto 按需适配
  → 已验收素材回填页面
  → 组装配置、原型、素材和配置指南
  → 校验并打包 DesignPackage
  → 批量发布为离线统一入口
```

页面 Skill、生图 Skill 和 OpenPhoto 均可独立调用。编排器只在需要自动素材回填、研究信号、多页面批次或恢复能力时参与。

## 8. 当前功能需求与实现

### 8.1 公共合同

- 使用公共 `DesignBrief`、`AssetRequest`、`AssetResult`、`DesignPackage` 等 Schema；
- capability ID 冻结，Skill 通过 manifest 声明能力和版本；
- 输入输出经过最小验证器校验；
- 页面配置使用严格、版本化的独立 Schema。

### 8.2 支付宝首页设计

- 接收 `deliverableType=alipay.home`；
- 固定保持搜索栏、轮播图、金刚区、豆腐块、腰封和商品推荐六个模块；
- 商品推荐保持组件快照内容，不生成商品数据；
- 金刚区允许 5–25 个入口并保持五列布局；
- 输出 `home-config.json`、原型、素材和配置建议；
- 联动任务可记录非生产的 `landingKey` 和相对 `landingPreviewRef`；
- 超出组件边界的要求返回结构化拒绝。

### 8.3 支付宝落地页设计

- 接收 `deliverableType=alipay.landing`；
- 在 `HERO_IMAGE`、`IMAGE_AD`、`SECTION_TITLE`、`COUPON_GROUP`、`PRODUCT_COLLECTION`、`ACTION_BUTTON`、`SPACER` 七类模块内组合；
- 商品和优惠券只表达待补资源，不编造真实业务数据；
- `ACTION_BUTTON` 仅在用户明确提出按钮、报名或跳转要求时规划；
- 输出 `landing-config.json`、原型、素材和配置建议；
- 失败素材显示诊断占位，不用默认图伪装为完整交付。

### 8.4 图片生成

- 接收结构化 `AssetRequest`；
- 支持 fal.ai 和 OpenAI-compatible provider；
- `AssetRequest` 可携带指定槽位的参考图，但只有显式声明 `asset.reference-images` 的外部 provider binding 才会接收；
- 当前内置 fal.ai 与 OpenAI-compatible binding 不消费参考图，标准编排会记录 warning 并退回文本约束生成；
- 输出文件路径、真实 MIME、宽高、SHA-256 和 provider 元数据；
- 只负责初始图片生成，不负责裁切或页面编排。

### 8.5 OpenPhoto 图片适配

- 支持确定性裁切、缩放和格式导出；
- 按页面素材请求的目标尺寸、格式和 `fit` 规则适配；
- 通过 revision 约束避免对过期文档状态继续操作；
- 由编排器共享一次运行中的浏览器进程并在结束时回收。

### 8.6 编排与批量生产

- 发现 Skill、验证 manifest，并匹配 capability provider；
- 按 `researchPolicy` 装配可选研究信号；搜索服务由调用方注入，编排器本身不直接联网；
- 对每个页面的待补素材执行生成、重试、适配、验收和二次回填；
- 单页最多五路并发生图，批次页面 item 保持顺序执行；
- 支持 `generate/reuse × required/optional` 素材策略；
- 支持 `run`、`resume` 和 `retry-failed`；
- 终态生成统一离线入口，仅发布成功页面；
- request、checkpoint 和结果中不保存 provider 密钥或完整私有 URL。

## 9. 输入

核心输入为 `DesignBrief`，包括：

- 任务 ID 和目标；
- `alipay.home` 或 `alipay.landing` 交付类型；
- 目标受众；
- 品牌、内容和视觉约束；
- 输出尺寸与格式；
- 可选参考图；
- `none`、`optional` 或 `required` 研究策略；
- 明确禁止修改的内容。

批量任务在此基础上增加 batch ID、item ID 和素材策略。输入不携带 provider 密钥，也不承载生产发布状态。

## 10. 输出与验收

### 10.1 页面设计包

| 产物 | 用途 |
|---|---|
| `home-config.json` / `landing-config.json` | 页面视觉设计的唯一配置事实 |
| `prototype.html` | 离线静态评审原型 |
| `prototype.png` | 可选的全页截图 |
| `assets/` | 页面实际引用的本地视觉素材 |
| `configuration-guide.md` | 面向运营的配置与待办说明 |
| `validation-report.json` | 自动校验结果 |
| `design-package.json` | 文件、哈希、来源和版本索引 |

### 10.2 批量交付

- `index.html`：全部成功页面的离线入口；
- `assets/`：按 item 隔离的最终素材；
- `configs/`：页面配置发布副本；
- `other/`：原型、截图、配置指南和审计文件；
- `other/runtime/`：请求、checkpoint 和最终结果。

### 10.3 验收规则

- `validation-report.passed=true`；
- 配置、原型、素材和配置建议来自同一页面配置；
- 必填素材满足请求合同中的目标比例，比例误差不超过 3%；
- 本地 `src` / `href` 文件存在且不越出交付目录；
- 组件结构和模块类型未超出 Catalog 与白名单；
- 生产资源和生产状态未被伪造。

## 12. 产品边界

### 12.1 套件负责

- 主题与受众驱动的页面视觉规划；
- 白名单内的模块选择、排序和受控文案；
- 页面视觉素材生成、比例适配和交付；
- 静态高保真原型、配置和运营建议；
- 自动校验、打包、批次恢复和结果追溯。

### 12.2 外部业务系统负责

- 真实商品、优惠券、价格、库存和领取资格；
- 资源查询、上传和系统资源 ID；
- 页面编码、生产路由与跳转校验；
- 草稿、发布版本、停用、回滚和缓存；
- 支付宝真机效果、运行时数据和最终上线验收。

## 13. 已知限制

1. 当前是产品形态验证版，不是生产就绪版本。
2. 页面设计受既有组件 Catalog 和模块白名单约束，不支持自由 HTML/CSS/JavaScript。
3. 人工视觉可用率尚未完成盲评，不能把自动校验通过等同于设计质量通过。
4. 真实 fal.ai 或 OpenAI-compatible 生图的质量、重复耗时和成本尚未形成统计基线。
5. Web Search 需要调用方注入服务；真实来源质量尚未重复评测。
6. OpenPhoto 当前依赖 Windows、Node.js 22 和系统 Chrome/Edge。
7. checkpoint 是单机文件状态，不提供数据库队列、跨机器锁或 exactly-once；极端中断可能造成 provider 重复计费。
8. 首页—落地页链接仅用于离线预览，不是生产跳转。
9. 组件快照和静态原型不能替代支付宝真机与生产业务校验。
